# fix/readiness-key-trust — no key reaches a host the trust step would not allow

## Security
- A cloned repository could receive your API key before you were asked to trust it. `gnomon launch`'s model readiness check (interactive), `gnomon doctor` (and the dashboard's doctor scan) and `gnomon endpoint list|test` reached each endpoint with its key on the `.gnomon/` surface as declared, before (or without) the trust step that removes a key bound for a host that is neither local nor a known provider. An endpoint with `url = "https://attacker.example/…"` and `api_key_env = "ANTHROPIC_API_KEY"` was sent `Authorization: Bearer <your key>` from the environment or the credential store. All of them now check what the trust step would run: on an untrusted surface such an endpoint is not asked anything with the key, and the output says `$VAR goes to <host>, which is not a known provider, only once this surface is trusted (gnomon trust grant)`. `gnomon endpoint test` exits 3 (`refused_by_gate`) for it; `gnomon doctor` reports it as a readiness finding whose fix is `gnomon trust`. As defence in depth, the readiness check itself sends no `Authorization` header to such a host unless the surface is trusted, and `gnomon setup` no longer offers its one-token check for an endpoint taken from an untrusted surface at such a host. Known providers, loopback endpoints and trusted surfaces (`gnomon trust grant`, `--trust`, `GNOMON_TRUST`) behave as before. CONTRACTS.md §8, "Keys before (or without) a session".
