# Findings, 2026-11-04: long tasks, hybrid on current builds, causal analysis

Every number here is bound to a committed result on the public
[`bench/peers-2026-11`](https://github.com/eljaplacido/gnomonharness/tree/bench/peers-2026-11/benchmarks/results)
branch. Each study was pre-registered before its data; the commit of the pre-registration and of the result are given.
n is small throughout. "Within one task" and "not shown" mean no difference was shown, never that the arms are
equivalent.

## 1. Long Terminal-Bench 4.0 tasks: why gnomon lost, and how far that is fixed

P2G attempt 1 (gnomon v0.3.1 vs peers; deepseek-v4.1-flash via OpenCode Go; 1,800 s cap): gnomon solved 1/29,
opencode 7, codex 7.

Reading: attempt 1's 7-vs-1 gap combined a fixed transport defect with a time-separated comparison. Run at the same
time, gnomon with the hosted recipe is within one task of opencode on 12 tasks. The recipe ships opt-in in v0.4.1
(`replay_reasoning`, `max_context_tokens = "auto"` or a declared window, `nudge_after_idle`); it is not a default.

## 3. Causal analysis of the long-task mechanisms (`causal-2026-11`)

With the causal platform's `causal-core` 0.13 and `causal-decision` (plan committed before any estimate; H1 held out):
reasoning replay, measured locally (M1a3, Glimmer): solved +0.23 [−0.005, +0.46]; delivering steering to the model
(S1): solved −0.12 [−0.37, +0.13]; the context window: refused (never varied). Every hosted-lane estimate was refused
with a typed reason. `causal-decision` verdict for each candidate default change: **experiment**. Paired sizing
(causal platform #107) puts a 10-point nudge test at about 110 task pairs. Commits 1ee43c62 → becdd75c.

## 4. What changed in gnomon because of this (v0.4.1)

Opt-in or record-only unless stated: `max_context_tokens = "auto"` (#137), per-call mediator records and an opt-in
calibrated token estimator (#144), a turn record that survives a kill (#143), log-only stall signals (#140; the idle
nudge fires on about half of runs that succeed anyway), and guard fixes found by property tests (#136, #141; tightening).
On a default surface the requests a model receives are byte-identical to v0.4.0 (release gate, #145).
