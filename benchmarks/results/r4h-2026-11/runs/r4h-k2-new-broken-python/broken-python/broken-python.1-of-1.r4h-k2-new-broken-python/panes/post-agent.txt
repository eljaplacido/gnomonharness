So every entry point died with `/usr/local/bin/python3: No module named pip`, including the `/usr/local/bin/pip3` wrapper. That shape — `dist-info` present, pac
kage tree gone — is what an interrupted upgrade or uninstall leaves behind.

I ruled the plausible alternatives out rather than assuming: no PEP 668 gate on this interpreter (the `EXTERNALLY-MANAGED` marker exists only for the distro 3.1
1 under `/usr/lib/python3.11/`), site-packages was writable, no `pip.conf` or `PIP_*` overrides, and a throwaway venv installed `six` from PyPI fine — so the in
dex and network were never the problem.

**The repair.** Moved the stale metadata aside and reinstalled pip from the wheel Python already ships, no network bootstrap:

```
mv .../site-packages/pip-24.3.1.dist-info /tmp/pip-24.3.1.dist-info.stale-bak
python3 -m ensurepip --upgrade --default-pip
```

```
$ python3 -m pip --version

$ python3 -m pip check

```

- `/tmp/pip-24.3.1.dist-info.stale-bak` is the old metadata, kept for recovery — safe to delete. `six` 1.17.0 is now installed system-wide as the proof; remove
