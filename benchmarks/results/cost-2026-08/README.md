# Cost to run the suite, per harness (B3)

Turns the already-measured per-harness token counts into a **dollar cost of
running the suite**, so gnomon's token-efficiency reads as money rather than an
abstract ratio — the framing a reviewer asked for. Generated by
`benchmarks/cost_report.py` from the committed `benchmarks/results/*.json`.

**Conflict of interest / provenance.** gnomon's author ran the underlying
internal 5-task suite. The token counts are the raw measured quantity; the
`$` figures apply uniform reference prices to them. The **ratio** between
harnesses is price-independent (same model, same tasks) — that is the robust
claim; the absolute `$` just makes it concrete.

## Headline — gnomon vs opencode (same model → pure token/cost ratio)

| model | opencode tokens vs gnomon | opencode cost vs gnomon |
|---|--:|--:|
| claude-sonnet-5 | 11.7× | **10.7×** |
| qwen3.6-35b | 7.4× | **6.8×** |
| gpt-5.3-codex | 6.3× | **5.4×** |
| qwen2.5-7b | 3.8× | **3.6×** |

Running the same 5-task suite, **opencode costs 3.6×–10.7× more than gnomon**,
because it spends that many more tokens per task.

## What this does and does not show

- **Robust:** the token/cost **ratio** across harnesses on the same model. gnomon
  is the cheapest effective harness in every cell (pi is comparable; opencode and
  omp are far more expensive).
- **Caveat — the internal suite's known limits carry over.** This is the small,
  author-run 5-task suite whose *harness-comparison timing/scoring* was partly
  retracted in the post-mortem. Token **counts** are less affected by that timing
  bias than pass-rates are, and the cost ratio here rests on the counts — but the
  `solved`/`$-per-solved` columns inherit the suite's scoring caveats, so read
  the pure token/cost ratio as the headline, not the solve counts.
- **No goose.** goose exposes no usage and isn't installed here, so it is absent
  — the same gap the roadmap's B3 (a shared usage-logging endpoint) exists to
  close.
- **Scope.** 5 tasks, one machine, reference prices. This makes the efficiency
  claim *concrete*, it does not broaden it.
