On PATH the default interpreter is `/usr/local/bin/python3` → **Python 3.13.1**. Its `site-packages` contained the pip *metadata* directory `pip-24.3.1.dist-inf
o` (and the `pip`/`pip3`/`pip3.13` entry-point scripts in `/usr/local/bin`), but the actual `pip/` package directory was **gone**:

- `pip-24.3.1.dist-info/RECORD` lists **841** files under `pip/`
- files actually present under `site-packages`: **10** (just `README.txt` + the dist-info files)

So the launcher scripts still existed and still pointed at a real interpreter, which is exactly why the failure looked like "pip is broken" rather than "pip is
missing":

```
File "/usr/local/bin/pip", line 5, in <module>
    from pip._internal.cli.main import main
ModuleNotFoundError: No module named 'pip'
```

`python3 -m pip` failed identically. This is the classic fingerprint of a `pip uninstall pip` or a botched cleanup — the dist-info survived, the code did not. N
ote also that `/usr/bin/python3` (Debian's 3.11.2) had no pip either, so there was no working fallback.

## The fix

Network is disabled in this sandbox, so I used the offline path. Python 3.13 ships its own pip wheel at `ensurepip/_bundled/pip-24.3.1-py3-none-any.whl`.

1. Moved the orphaned `pip-24.3.1.dist-info` to `/tmp/pip-24.3.1.dist-info.orphaned.bak` — otherwise pip's installer can see the stale metadata and consider the
 requirement already satisfied, reinstalling nothing.
2. Ran `python3 -m ensurepip --default-pip`, which installed pip 24.3.1 from the bundled wheel.
