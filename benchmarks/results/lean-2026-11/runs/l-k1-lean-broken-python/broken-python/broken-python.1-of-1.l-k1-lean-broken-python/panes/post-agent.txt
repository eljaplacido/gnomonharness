## What was wrong

Not a permissions or config problem — pip's actual code was missing.

```
/usr/local/lib/python3.13/site-packages/
├── pip-24.3.1.dist-info/   ← metadata present
└── (no pip/ directory)     ← the package itself was gone
```

So `/usr/local/bin/pip3` existed and ran, but died on its first import:

```
ModuleNotFoundError: No module named 'pip'
```

Something deleted the `pip/` package directory while leaving its `dist-info` behind. This also meant the usual repair, `python3 -m ensurepip --upgrade`, silentl
y no-opped with *"Requirement already satisfied: pip"* — it saw the stale metadata and assumed pip was installed.

## What I did

1. Moved the orphaned `pip-24.3.1.dist-info` aside (backup kept at `/tmp/pip-24.3.1.dist-info.broken.bak`).
2. Ran `python3 -m ensurepip --upgrade`, which reinstalled pip 24.3.1 from the bundled wheel in `/usr/local/lib/python3.13/ensurepip/_bundled/` — no network nee
ded.

## Verification

- `pip3`, `pip`, `pip3.13` all report `pip 24.3.1 from /usr/local/lib/python3.13/site-packages/pip (python 3.13)`
- `pip3 check` → `No broken requirements found.`
- Real install works: installed `six` to a scratch target and imported it successfully (`1.17.0`)
- All 852 files listed in pip's `RECORD` now exist — the installation is complete, not just importable

## Two things worth knowing

**`/usr/bin/python3` (3.11) has no pip at all**, and it's marked `EXTERNALLY-MANAGED`, so Debian intends for you not to install into it directly. I left it alon
e. Use `/usr/local/bin/python3` (3.13) — it's first on your `PATH`, so plain `python3`/`pip3` already resolve there.

**You're running pip as root into the system interpreter**, which is what let a bare `rm` break it in the first place. For anything you actually need, `python3
-m venv` will keep future damage contained. If you want, I can also raise pip to 26.2.2 — it flagged that upgrade as available, but I didn't apply it since you
didn't ask and the version you have now works.
