## Two things to know

**A second, separate Python exists and still has no pip.** `/usr/bin/python3` is Python **3.11.2**, distinct from the 3.13.1 you were hitting. It has no pip eit
her, but I left it alone on purpose: it carries `/usr/lib/python3.11/EXTERNALLY-MANAGED`, so it's a distro-managed interpreter where system-wide `pip install` i
s blocked by design. Using `pip` against it is the wrong move — use `python3 -m venv` there. Your 3.13 has no such marker, so it accepts installs.

**Your pip is 24.3.1 and 26.2.2 is available.** I did not upgrade it, since that wasn't the problem and upgrading a system pip is a change you may want to make
deliberately. When you do, prefer `python3 -m pip install --upgrade pip` in a user or venv context.

Root cause is worth a second look on your side: pip's code was removed but its metadata wasn't, so whatever deleted it ran non-atomically. If that was an image
build or a provisioning script, it will likely do the same thing again on the next run.
