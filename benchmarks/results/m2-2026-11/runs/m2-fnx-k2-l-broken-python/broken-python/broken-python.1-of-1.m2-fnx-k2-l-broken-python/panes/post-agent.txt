## The trap worth knowing about

The obvious fix — `python3 -m ensurepip --upgrade` — **silently did nothing** on the first try:

```
Requirement already satisfied: pip in /usr/local/lib/python3.13/site-packages (24.3.1)
```

Because the orphaned `.dist-info` is what pip uses to decide what's installed, it kept reporting pip 24.3.1 as present. This is the state that makes the breakag
e sticky: the tool's own ledger claims it's fine. Removing the stale metadata was the necessary step; only then did `ensurepip` actually reinstall.

I verified the bundled wheel before trusting it rather than assuming it was intact: zip integrity OK, 437 entries, and all 437 `RECORD` sha256 hashes recomputed
