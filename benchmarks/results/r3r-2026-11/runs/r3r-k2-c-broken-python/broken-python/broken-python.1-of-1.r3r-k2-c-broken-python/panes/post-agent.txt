**What was wrong:** the `pip` package directory itself was missing from `/usr/local/lib/python3.13/site-packages/` — only the orphaned `pip-24.3.1.dist-info` me
tadata was left behind. So `/usr/local/bin/pip3` existed and ran, but died on `from pip._internal.cli.main import main` with `ModuleNotFoundError: No module nam
ed 'pip'`. Nothing was wrong with your PATH, proxies, or pip config (there is no pip.conf anywhere); the script was fine, the module it imports was gone.

**Why the obvious fixes didn't work:** `python3 -m ensurepip --upgrade` bails out with "Requirement already satisfied: pip in ... (24.3.1)" — it trusts the stal
e metadata and never restores the files. It's worth knowing, because it looks like it succeeded.

**The fix I applied:** installed the bundled wheel directly, forcing the reinstall and skipping the metadata check:

```
python3 /usr/local/lib/python3.13/ensurepip/_bundled/pip-24.3.1-py3-none-any.whl/pip \
  install --force-reinstall --no-index --no-cache-dir \
  /usr/local/lib/python3.13/ensurepip/_bundled/pip-24.3.1-py3-none-any.whl
```

That runs pip's zipimport entry point from inside the wheel, so it works without a working pip, and needs no network.
