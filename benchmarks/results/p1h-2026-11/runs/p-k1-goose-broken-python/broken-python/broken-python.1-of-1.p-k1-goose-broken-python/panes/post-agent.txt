Fixed. Here's what was wrong and what I did.

## Root cause

Your system-wide interpreter is a source-built **Python 3.13.1** at `/usr/local/bin/python3`, with site-packages at `/usr/local/lib/python3.13/site-packages`.

In that directory, only these were present:

```
README.txt
pip-24.3.1.dist-info/     ← metadata intact
```

The `pip-24.3.1.dist-info` folder was there, but the **actual `pip/` package directory had been deleted**. Its RECORD file still listed all 852 installed files,
 so this was a partial/failed uninstall (or an interrupted upgrade) that removed the code but left the metadata behind.

That produced the confusing symptom:

```
$ pip --version
Traceback (most recent call last):
  File "/usr/local/bin/pip", line 5, in <module>
    from pip._internal.cli.main import main
ModuleNotFoundError: No module named 'pip'
```

The `pip` launcher scripts (`/usr/local/bin/pip`, `pip3`, `pip3.13`) were fine — only the module they import was missing.

Note this was *not* a PATH, permissions, or network problem.

## The fix

1. Moved the stale metadata aside (`pip-24.3.1.dist-info` → backup) so the installer wouldn't think pip was already installed.
2. Reinstalled from the bundled wheel that ships with your Python:

```bash
python3 -m ensurepip --upgrade --default-pip
```

This installed pip 24.3.1 from `/usr/local/lib/python3.13/ensurepip/_bundled/pip-24.3.1-py3-none-any.whl` — no network needed.

I then uninstalled the test package and removed the temp backup, so the system is back to a clean state apart from the repaired pip. I also scanned all site-pac
kages for other `.dist-info` folders with missing code — **none found**, so pip was the only casualty.

## Two things worth knowing

- **Use a virtualenv for real work.** You're root on a Debian-based image, and pip itself warns that writing to the system prefix can conflict with the OS packa
ge manager. Your source-built 3.13 isn't apt-managed so it's lower-risk, but `python3 -m venv .venv` is still the safer habit.
- **`/usr/bin/python3.11` also has no pip** — but that's Debian's own interpreter and Debian deliberately ships it without pip/ensurepip. If you ever need it, u
se `apt install python3-pip` rather than `ensurepip`, since apt installs it into the Debian-managed location. Your default `python3` on PATH is the 3.13 one, so
 this doesn't affect normal use.

To avoid a repeat, don't `rm -rf` a package directory to uninstall it — use `pip uninstall <pkg>`, or if things get wedged, `pip install --force-reinstall <pkg>
`.
