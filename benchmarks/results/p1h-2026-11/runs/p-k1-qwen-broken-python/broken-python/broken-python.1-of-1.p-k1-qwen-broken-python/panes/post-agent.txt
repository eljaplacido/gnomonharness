## Root cause

Your default `python3` is `/usr/local/bin/python3` (3.13.1, `sys.prefix=/usr/local`). Its `site-packages` had been **half-removed**:

```
/usr/local/lib/python3.13/site-packages/
├── README.txt
└── pip-24.3.1.dist-info/    ← metadata present
```

The `pip/` package directory itself was gone, but pip's `.dist-info` metadata survived. So:

- `/usr/local/bin/pip` still existed and tried `from pip._internal.cli.main import main` → `ModuleNotFoundError: No module named 'pip'`
- Python's metadata subsystem still saw pip 24.3.1 as "installed", because that's all `.dist-info` is

That mismatch is what made it hard to fix casually: `python3 -m ensurepip` **appeared to succeed** — exit 0, `Requirement already satisfied: pip in ... (24.3.1)
` — while restoring nothing at all.

## What I did

1. Moved the orphaned `pip-24.3.1.dist-info` to `/tmp/pip-orphan-backup-1793495775` (moved, not deleted, so it's reversible).
2. `python3 -m ensurepip --upgrade --default-pip` — reinstalled pip from the wheel bundled in the stdlib at `ensurepip/_bundled/pip-24.3.1-py3-none-any.whl`. **
No network required.**
