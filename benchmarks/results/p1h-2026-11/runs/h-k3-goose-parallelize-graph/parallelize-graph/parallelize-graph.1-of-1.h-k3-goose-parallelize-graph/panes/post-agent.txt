## Algorithm (Georganas et al., SC'14 formulation)
- Nodes = unique k-mers (2-bit encoded in `uint64_t`), hash table with **separate chaining**; node → at most one successor (`kmer[1..k-1]+rightExt`), in-degree
from ≤4 candidate predecessors.
- Contigs = maximal non-branching paths, each uniquely identified by its start node (in-degree ≠ 1); residual nodes lie on pure cycles and are emitted once from
 the cycle's smallest k-mer (layout/thread-count independent).

## Parallelisation in UPC
1. **Parallel input** — file split into `THREADS` byte ranges (line-boundary aligned), each thread parses with its own `FILE*`.
2. **Hash redistribution** — histogram + `THREADS×THREADS` count matrix in shared memory drives an all-to-all exchange, so each thread owns a contiguous, exclus
ive slice of the shared node array.
3. **Local chain building** — bucket space partitioned evenly too → **no locks, no atomics, no remote updates**.
4. **Parallel traversal by ownership** — each thread walks only contigs starting at nodes it owns; a shared visited array (single writer per node) makes cycle d
etection race-free.
5. **Parallel output** — each thread writes its own `pgen_<thread>.out`.
